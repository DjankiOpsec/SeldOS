# SKILL_TOR: Sovereign Tor Browser & OpSec Gateway in SeldOS
### Практическое руководство и инженерный навык по работе с суверенным браузером SeldOS, шлюзом OpSec и Tor-сетью

---

## 1. Обзор архитектуры и принципы работы

В SeldOS реализован двухконтурный механизм анонимного и защищенного веб-серфинга:

```
+-----------------------------------------------------------------------------------------+
|                                    SeldOS Ring 3                                        |
|  /bin/tor (Графический браузер 680x334x32bpp, DuckDuckGo .onion SERP, HTML-движок)      |
+-----------------------------------------------------------------------------------------+
                                           |
                   MSR SYSCALL / SYSRET (sys_tcp_connect, sys_dns_resolve)
                                           v
+-----------------------------------------------------------------------------------------+
|                                  SeldOS Humboldt Kernel                                 |
|  Сетевой стек: E1000 / PCnet PCI NIC -> ARP -> IPv4 -> ICMP -> UDP (DNS) -> TCP Sockets |
+-----------------------------------------------------------------------------------------+
                                           |  (10.0.2.15 -> 10.0.2.2)
                                           v
+-----------------------------------------------------------------------------------------+
|                                      Хост (Linux)                                       |
|  Контур 1 (Pure Onion): 127.0.0.1:9050 -> Tor SOCKS5 Daemon (Remote Resolution)          |
|  Контур 2 (OpSec Web):  0.0.0.0:8080   -> opsec_gateway.py (TLS 1.3, Sanitizer, Mirror) |
+-----------------------------------------------------------------------------------------+
                                           |
                                           v
+-----------------------------------------------------------------------------------------+
|                         Глобальная сеть / Tor Network                                  |
|  - DuckDuckGo .onion (duckduckgogg42xjoc72x3sjasowoarfbgcmvfimaftt6twagswzczad.onion)   |
|  - Защищенный HTTPS клирнет через TLS 1.3 Termination                                  |
+-----------------------------------------------------------------------------------------+
```

### Два маршрута трафика:
1. **Onion Services (`onion://...`):**
   - Прямой SOCKS5-хэндшейк из SeldOS на порт 9050 хоста (`10.0.2.2:9050`).
   - Имя хоста `.onion` передается внутри фрейма SOCKS5 без предварительного DNS-запроса (RFC 1928 ATYP=0x03, делегирование резолвинга демону Tor).
   - Для сложных страниц (DuckDuckGo Onion SERP) шлюз `opsec_gateway.py` выполняет защищенный парсинг и передает в SeldOS компактную структуру данных.
2. **Clearnet & HTTPS (`https://...`):**
   - Поскольку полноразмерный криптостек TLS 1.3 требует сотен мегабайт сторонних библиотек, SeldOS использует концепцию **OpSec Gateway**: соединение идет к локальному шлюзу на порт `8080`, который валидирует системные корневые сертификаты (Root CA), декомпрессирует gzip/brotli, очищает страницу от рекламы/трекеров/JS и отдает легковесный семантический HTML в браузер.

## 2. Быстрый запуск (Quick Start)

### Шаг 1. Запуск фоновых служб на хосте
```bash
# 1. Запуск демона Tor SOCKS5 (если не запущен)
tor --DataDirectory /tmp/tor_data --SocksPort 9050 --Log "notice stdout" &

# 2. Запуск OpSec Gateway на порту 8080
python3 scripts/opsec_gateway.py --daemon

# 3. Проверка статуса служб
python3 scripts/opsec_gateway.py --status
curl --noproxy "*" -s http://127.0.0.1:8080/
```

### Шаг 2. Сборка системы и запуск эмулятора
```bash
# Сборка libc, утилит, браузера и ISO
make all

# Запуск SeldOS в QEMU с эмуляцией сетевой карты e1000
make qemu
# Или с кастомными параметрами:
qemu-system-x86_64 -cdrom build/seldos.iso -drive file=build/disk.img,format=raw \
    -net nic,model=e1000 -net user -vga std -m 256
```

### Шаг 3. Запуск браузера в SeldOS
В терминале SeldShell (`snl$`):
```bash
# Проверить получение IP и доступность шлюза
ifconfig
ping 10.0.2.2

# Скачать бинарник браузера из локального репозитория шлюза
download tor

# Запустить браузер
tor
```

## 3. Горячие клавиши и управление браузером

### Навигация и ввод:
- `O` или `/` или `L`: Активировать адресную строку (ввод URL или поискового запроса).
- `Enter`: Загрузить введенный адрес или поисковый запрос.
- `ESC`: Отменить редактирование URL / Выйти из браузера обратно в SeldShell.
- `Backspace`: Удаление символа в адресной строке.
- `R`: Перезагрузка текущей страницы.
- `N`: Новая личность (New Identity) — сброс сессий и истории.
- `H`: Возврат на домашний портал (`home`).
- `Q`: Выход из браузера.

### Скроллинг страниц (решение проблемы отсутствия колеса мыши в PS/2):
- `Space`: Скролл вниз на одну страницу (Page Down).
- `Shift + Space`: Скролл вверх на одну страницу (Page Up).
- `j` / `k`: Быстрый скролл вниз/вверх (Vim-стиль).
- `Стрелки Вверх / Вниз`: Плавный скролл по 24 пикселя.
- `Home` / `End`: Мгновенный переход в начало/конец страницы.
- **Мышь:** Кликните в любое место полосы скроллбара справа (x=650) или зажмите левую кнопку и перетаскивайте ползунок вертикально.

### Быстрые закладки (цифровые клавиши):

## 4. Поисковая система DuckDuckGo .onion

### Как работает поиск:
Если в адресную строку ввести слово **без точки** (например, `temple`, `linux`, `tux`, `freebsd`), браузер автоматически направляет запрос в **DuckDuckGo Sovereign Search Engine (.onion)**:
```
onion://duckduckgogg42xjoc72x3sjasowoarfbgcmvfimaftt6twagswzczad.onion/?q=ВАШ_ЗАПРОС
```

### Элементы интерфейса выдачи (SERP):
1. **Логотип Dax (слева вверху):** Клик возвращает на домашний портал `home`.
2. **Поисковая плашка:** Отображает текущий запрос. Клик переводит в режим ввода нового запроса.
3. **Вкладки категорий (`Q All`, `Images`, `Videos`, `News`):** Кликабельны, позволяют фильтровать результаты.
4. **Левая колонка выдачи:** 8–10 подробных результатов с фавиконами, доменами, заголовками и сниппетами. Вся площадь карточки (350×64 px) кликабельна для перехода на сайт.
5. **Правая колонка (Knowledge Card):** Информационная карточка объекта с графической обложкой, текстом из энциклопедии и источником. Клик открывает полную статью.

## 5. Внутреннее устройство компонентов (`userspace/bin/tor/`)

| Файл | Назначение | Ключевые функции |
|---|---|---|
| `main.c` | Главный цикл событий, двойная буферизация, GUI | `render_page()`, `draw_frame()`, `render_screen()`, `load_url()` |
| `ddg_serp.c` | Рендеринг и парсинг выдачи DuckDuckGo | `ddg_serp_render()`, `ddg_serp_parse()`, клиппинг шрифтов |
| `http.c` | HTTP/1.1 клиент, маршрутизация SOCKS5 / Gateway | `http_fetch()`, DNS fallback, управление сокетами |
| `html.c` | Легковесный рендерер HTML, ссылки, теги, сущности | `html_render()`, пропуск `<script>`/`<style>`, хитбоксы |
| `socks5.c` | Нативный протокол SOCKS5 (RFC 1928) для Tor | `socks5_connect()` с `ATYP=0x03` (Domain Name) |

### Производительность и двойная буферизация:
Для исключения лагов при движении мыши статический контент страницы рендерится один раз в буфер `s_page_buf`.
При перемещении мыши вызывается только функция `draw_frame()`:
```c
static void draw_frame(void) {
    memcpy(s_backbuf, s_page_buf, SCR_W * SCR_H * sizeof(uint32_t));
    s_draw_target = s_backbuf;
    draw_cursor(s_mouse_x, s_mouse_y, s_prev_mouse_btn);
    memcpy(s_fb.framebuffer, s_backbuf, SCR_W * SCR_H * sizeof(uint32_t));
}
```
Это занимает **менее 0.2 мс** на кадр, обеспечивая 60+ FPS без нагрузки на процессор.

## 6. Санитаризация HTML и решение проблем с версткой

### Проблема «сырых данных» (Raw HTML / JS / Menus):
Современные сайты содержат мегабайты JavaScript, CSS и огромные панели навигации (например, список из 27 языков в Википедии).
В `scripts/opsec_gateway.py` реализован интеллектуальный фильтр:
1. **Выделение смыслового ядра:** Нацеливание на `mw-parser-output`, `article`, `main`, отсекающее заголовки и выпадающие списки языков.
2. **Декомпозиция мусора:** Удаление тегов `<script>`, `<style>`, `<nav>`, `<aside>`, `<svg>`, трекеров и пустых ссылок.
3. **Нормализация Unicode (`clean_text_for_seldos`):** 
   - Символы с диакритикой (`č`, `š`, `ñ`, `ə`) конвертируются в чистый ASCII (`c`, `s`, `n`, `e`).
   - Исключаются пустые линии подчеркиваний `___________` от нераспознанных шрифтом символов.
   - Кириллический диапазон (`0x0400`–`0x04FF`) сохраняется в исходном виде.

## 7. Диагностика и устранение неполадок (Troubleshooting)

### Ошибка: `Connection Refused / Gateway Offline (code -8 или -14)`
- **Причина:** Не запущен `opsec_gateway.py` на хосте.
- **Решение:** Выполните на хосте:
  ```bash
  python3 scripts/opsec_gateway.py --daemon
  ```

### Ошибка: `Tor SOCKS5 Daemon Offline (code -10)`
- **Причина:** Демон Tor на порту 9050 не отвечает.
- **Решение:** Проверьте вывод `ss -tulpn | grep 9050`. Запустите демон `tor --SocksPort 9050`.

### Ошибка: `DNS Resolution Failed (code -3)`
- **Причина:** Недоступен DNS-сервер 10.0.2.3:53 или сеть QEMU.
- **Решение:** В SeldOS выполните `ping 10.0.2.2`. Если пинг не идет, убедитесь, что QEMU запущен с флагами `-net nic,model=e1000 -net user`.

### Тестирование сквозных сценариев (Automated Tests):
Для автоматизированной проверки снимите скриншоты через QMP-тесты:
```bash
# Проверка взаимодействия, скролла, мыши и рендеринга внешних сайтов
python3 tests/verify_browser_fixes.py

# Проверка выдачи DuckDuckGo .onion SERP
python3 tests/verify_ddg_serp.py
```
Скриншоты сохраняются в папку `scratch/` и `tests/`.

## 8. Архитектура сетевой безопасности
1. **Remote DNS Resolution (RFC 1928):** Имена хостов `.onion` и проксируемых ресурсов передаются напрямую в теле SOCKS5-хэндшейка (ATYP=0x03) без обращения к локальному системному UDP DNS резолверу ядра (порт 53).
2. **RAM-Only Execution:** Браузер не пишет кэш, историю или куки на диск SeldFS. При закрытии память затирается нулями (`memset(..., 0, ...)`).
3. **No JavaScript Execution:** Движок не исполняет клиентские скрипты, исключая класс эксплойтов браузерного песочника, переполнения JIT-компиляторов и деанонимизацию через Canvas/WebGL фингерпринтинг.
